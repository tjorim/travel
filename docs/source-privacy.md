# Source privacy

The personal instance may retain real trips, documents, uploads, local archives
and private recovery copies. Keep that data out of public source and GitHub
issues, pull requests and build artifacts.

Use invented trip names, booking details and dates in fixtures, examples and
screenshots. Public place names and IANA time zones are fine for geographic
and daylight-saving tests; preserve the calendar relationships those tests need.

Review files before committing. Do not copy production responses, personal
itineraries, booking documents, credentials or authenticated production
screenshots into Git. Keep local databases, uploads and backups ignored or
outside the source tree. Synthetic UI assets and examples can be committed
after review.
